USING THE BENCHMARK

Bring a model. Keep the evidence.

Choose a workcell, input track, exact model label, and repair budget. Import a self-contained Lab Studio JSON for the assisted track, then start the run. Inputs and grading conditions are frozen for that run.

In a browser agent host with native WebMCP, enable site tools and give the agent the copied instructions. It can inspect capabilities, stage a task, validate, run, repair within budget, and finalize. In other browsers, paste the model’s code or import its task bundle and use the same visible controls; those actions are labeled manual.

The static site does not call model APIs or choose models for you. It evaluates the program a model builds through a compatible agent host.

What the score does—and does not—mean

Scores measure configured robot-motion goals in fixed public workcells. SO-101, OpenArm, and LeKiwi replay Python-generated actions through RoboBuddy’s source plant. Their Python observation shim is not a live sensor loop. G1 is kinematic-only. MicroDuck runs live policies over approximate browser dynamics.

Workflow coverage is structural, not chemical validation. Mark unsupported and human-only steps honestly. Additional assets are visual-only; editing workcell.py does not change physical geometry. This is a transparent development benchmark, not a hidden, adversary-resistant leaderboard or a hardware qualification test.
